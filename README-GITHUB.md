# Tandem（协动）

**让团队围绕任务与 AI Agent 协同交付，让每次执行的经验成为项目下一次工作的上下文。**

Tandem 是面向研发团队的人机协同平台方案与交互原型。它以项目组织团队工作，以任务承载目标、澄清、执行、验收和产物；Agent 是可替换的执行者，团队始终掌握任务定义和交付验收。

> 当前仓库包含产品与技术设计文档，以及可交互的前端演示原型。原型使用模拟数据，不连接真实任务源、Agent、身份系统或多人实时服务。

## 为什么做 Tandem

团队开始使用 Agent 后，挑战不只在于生成代码，还包括如何把模糊需求变成可执行任务、让多人共享上下文、检查 Agent 产出、追踪责任，并把有效经验留在项目里。

Tandem 围绕这些团队工作事实设计：

- **项目组织工作**：项目承载成员、任务和共享资产，团队在项目维度持续协作。
- **任务驱动协同**：任务是唯一工作单元，成员围绕同一任务面板澄清、分工、执行、讨论与验收。
- **信息不完整时先澄清**：任务停留在 `backlog`，团队逐项补充信息并确认任务契约后，才进入执行队列。
- **人负责交付判断**：Agent 提交结果和证据，授权验收人决定通过、打回或阻塞。
- **项目经验持续积累**：任务产物先关联来源任务并经过治理，再成为后续任务可以检索的上下文。

## 协同闭环

```text
项目中的业务信号
       ↓
任务板创建 backlog 卡片
       ↓
团队受理、讨论并澄清缺失信息
       ↓
确认任务目标、范围和验收标准
       ↓
派发 Agent 执行，持续观察进展与证据
       ↓
人工验收、打回返工或确认完成
       ↓
产物沉淀到项目，经治理后供后续任务引用
```

任务状态沿用七态流程：`backlog`、`todo`、`in_progress`、`in_review`、`blocked`、`done`、`canceled`。会话记录一次执行过程，不取代任务；上下文服务按任务提供项目资料，不成为另一个任务来源。

## 快速预览

原型是无需构建的静态 HTML、CSS 和 JavaScript 页面。克隆仓库后，在仓库根目录运行：

```bash
python3 -m http.server 8080
```

打开：

```text
http://localhost:8080/prototype/index.html?view=board&tenant=pay-settle&task=PAY-2048
```

演示路径：

1. 在项目任务板打开退款结算反馈对应的积压卡。
2. 受理信号，在任务面板提出澄清问题并逐条答复。
3. 确认任务契约和上下文，再派发 Agent 模拟执行。
4. 查看执行会话、提交证据、验收或打回。
5. 完成后演示将可复用产物登记到项目。

演示中的结算反馈只是场景入口，不定义真实业务规则。执行输出、测试结果、成本和项目成员均为模拟数据。

## 当前状态

- 已完成：产品方案、DDD 技术设计、任务协同场景故事、静态交互原型。
- 原型覆盖：七态任务板、任务面板澄清、单浏览器角色切换、Agent 模拟执行、人工验收、审计与项目资产演示。
- 尚未接入：真实任务系统、真实 Agent 执行、持久化后端、企业身份与权限服务、多人实时协作、生产级上下文检索与资产治理。
- 技术选型与开源项目能力属于设计候选，落地前需要按目标环境重新验证版本、许可证、安全和集成能力。

## 适合一起讨论

- 团队的最小任务契约应该包含哪些信息？
- 哪些项目资料可以被 Agent 检索，谁负责审核和过期维护？
- 如何衡量 Agent 是否让同类任务更快、更可靠地完成？
- 哪些验收、权限和发布规则应由项目配置？

## 项目定位

**任务是团队与 Agent 之间的工作契约；项目是任务协作和经验积累的边界。** Tandem 把人的判断、Agent 的执行和项目的长期记忆连接在同一个可追溯的工作流里。
