# 设计决策与开放问题

## 已采用

- 保持两个前端和共享模块化后端：员工 Portal 面向工作，console 内企业与平台壳分别授权。通过共享包复用，不跨应用导入源码。
- 企业身份、平台授权、显式项目成员资格互不替代；平台运营仅看聚合，不取得项目内容权限。私人搭档及自动化没有管理员读取绕过。
- 任务是持久规划，运行是实际尝试。工具审批、运行结果认可与任务验收分开；任务提交后由独立经理验收，运行成功不会自动完成任务。
- 每个企业/用户一个真实私有默认项目。本人未归属执行通过授权投影展示，保留不可变原始项目归属；不创建虚构任务，不另设个人历史列表。
- 个人搭档采用独立的文本受限版本策略，不挂工具、知识或记忆；共享任务只支持人工与企业 Agent。便利不能隐式扩大私人数据可见性。
- 自动化保存私人日程与发生记录，不生成周期项目任务。停机有限补跑、重叠跳过；日程推进、配额、实际运行、队列和审计事务提交。
- 使用数据库约束、锁、乐观版本、事务审计及 outbox 保护并发。保留所有历史迁移，以新增迁移演进；不直接重写旧版本。
- 工具调用保留稳定幂等键与结果账本，未知副作用停止自动重放并人工核对；不承诺外部绝对 exactly-once。
- 生产配置失败关闭；假模型和 loopback 例外仅测试可用；seed 禁用于生产。环境加载锚定本项目，不搜索父目录或用户配置。
- 后端由运行时依赖 tsx 执行 TypeScript，前端独立构建静态镜像；发布能力以目标环境验证为准。

## 开放问题

- 私人工具、知识和记忆需要怎样的资源所有权、检索授权和撤销机制？当前不开放。
- 项目背景自动注入、知识发布和资产版本管理如何保留来源与授权？当前不支持。
- 默认项目不可共享且不允许自验收，如何让用户及时识别应转入共享项目的工作？
- API 横向扩容前如何提供共享限流与通知？当前按单 API 副本运行。
- 企业暂停、注销及平台生命周期尚需完整身份、执行和保留策略，不以简单状态开关代替。
